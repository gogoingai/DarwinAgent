# Oak 框架修复与 LoCoMo 三集合重跑

> 下文原记录属于 0.2.0 历史方案。当前 0.3.2 的固定框架、98 项检查和失败冷启动记录见本文末尾「2026-10-03」。H、`oak_domains` 和旧生成循环已移除，旧分数不作为新框架基线。

开始日期：2026-10-02。执行依据：`PORTABILITY-PLAN.md` 及用户追加要求。

## 本轮边界

- 内核分为 **S / F / C / P / H**。H 是 harness，指检索、工具执行、上下文组织、候选与输出核查等可版本化运行策略。
- 框架底线、模型传输、预算持久化和文件事务属于引擎，不因加入 H 就成为任意自动修改代码的入口。
- 用户明确禁止修改评测。本轮保留现有 judge、protocol、归因器、gold 修复表和数据内容；日期等评测依赖也冻结。共享拒答常量所在 `prompts/answer.py` 一并保持不变，新的生成策略置于领域 harness。
- 框架修复按契约、可靠性与已验证的移植能力验收；<3% 不作为框架修复验收条件。
- 后续迭代的收敛目标是冻结归因口径下 **评测外错题数 / 全部题目数 < 3%**。执行/评测未完成不能报达标；严格小于通过整数交叉乘法判断，避免四舍五入误报。
- 正文、observation、event_summary 的来源范围沿用当前系统，报告披露；没有增加外部答案来源。

## 已实施的第一批修复

- 实体、属性、主键、dtype、关系签名和 functional 冲突在通用建图入口校验；隔离模式明确记录污染候选。
- 节点 ID 改为保留结构和类型的序列化，避免字段分隔符造成错误合并；新图记录格式版本。
- 抽取端白名单由本轮 Schema 生成；图指纹包含完整语料和构建资产，生成续跑绑定图与 harness。
- event_summary 具有独立来源定位，终答仍标为摘要，不能因补齐定位就提升为正文证据。
- 内核登记增加 H、完整摘要及执行依赖；提供资产导出/装载和独立候选补丁，评测不是合法补丁目标。
- fast 未显式配置时继承主服务；角色路由可以通过配置注入。
- 显式命名空间预算覆盖其子调用，预留计数原子写入并支持重启恢复。
- 槽位提取器改为与图一致的上下文隔离；生成函数试跑超时可以结束工作进程。
- 形式推理未完成明确成为 UNVERIFIED，要求 HermiT 的调用不会将其当作通过。
- 统一构建与推理阶段入口已接入 LoCoMo；输出证据完整性与拒答协议检查在发布评测前执行。

追加修复：旅行领域计算迁入 `oak_domains`；领域角色不再登记在核心；两任务接入公共阶段编排。预算加跨客户端/进程文件锁并同时检查嵌套 scope。关系算子统一读取主键视图；形式映射修正 union domain 和实际 min/max 基数。候选补丁用临时目录验证后发布。

这些修复尚不表示整份可移植方案全部完成。完整自动学习控制器、领域模块独立执行、资产增删与自动采纳门控仍未完成，详见 `PORTABLE-USAGE.md`；本轮真实成绩按实际完成情况更新。

`summary.json` 为 `failed`。四种指标的零值是故障占位，不能报告为 0% 的有效模型测量、改善或收敛。失败结果、原始响应、资产、提案、逐题故障、拒绝理由与身份均保留。

具体归因：

- **B0 输出协议/传输失败：** 一个抽取批次 JSON 在字符串中截断；外部 fast 模型多次只输出思考内容。另一个批次输出 `values(Person→Work)`，生成的 S 只允许 `values(Person→Item)`。前者属于模型/传输输出可靠性，后者涉及初始化 S/P 设计与模型契约遵循；框架按类型拒绝，没有后处理补救。
- **R1 引文协议失败：** 三次输出都把原文 `上周五,我去参加了一个LGBTQ+心理咨询工作坊` 的半角逗号改成全角逗号。来源 ID 在当前批次中真实存在，但 quote 不再是逐字子串，故来源检查拒绝。不是已证实的凭空事实。当前批次失败会阻止整个图进入答题，且错误反馈仅给出来源/引文错误，暴露了固定抽取流程在故障定位和恢复粒度上的可用性限制；本轮没有放松来源检查或替换引文。
- **R2 提案协议失败：** `find_events_by_subject` 的基准指纹被模型复制错一个字符。修订服务拒绝陈旧/错误基准，未自动修正哈希、改写原资产或绕过准入。该阶段没有完整评分，不能采纳。

本实验记录 41 条模型返回台账，其中 19 条为空正文；台账报告 prompt tokens 1,117,964、completion tokens 822,363。部分返回没有 usage，以上是已报告量，不是精确计费总额。B0 生成/评测阶段耗时 701.38 秒，R1 为 913.94 秒；初始化、提案和其他失败启动另有原始记录。两阶段的评测接口记录了生成故障，因没有正常答案，未调用模型评分；评测故障计数 0 不等于完成了评测。

## 2026-10-03：固定框架 0.4.0——原子事实两阶段与三集合迭代（工程定版）

针对 0.3.2 冷启动失败的逐项归因（批次 JSON 截断、fast 档空正文、S 与模型输出不匹配、引文标点被改写、单批失败阻断全图），按《原子事实记忆与三集合迭代跑测方案》完成工程定版：

- **两阶段拆分**：`ExtractionAgent.extract(corpus)` 只产出 `MemoryResult`（不可变原子事实，id=来源定位+规范化内容推导，往返篡改可检）；`GraphAssembler.build(memory,spec,schema)` 按 S 声明映射确定性构图。抽取按消息边界分批（批正文 ≤2000 字符）、超长消息独立成批保留偏移、明确截断固定二分 ≤2 层、逐条校验错误指明事实/字段/来源、引文逐字+偏移不改写。
- **事实锚定不变量**（用户澄清后定稿）：图来自记忆；每条事实是一等公民记忆节点（`__fact__` 完整定义），图上复原指纹==记忆指纹（round-trip）；一切结构回溯记忆节点、无游离结构。S 为 checked-in 固定种子（六类型+七关系+实体分类），冷启动只生成 F/C/P，提案只可对 S 只增不删扩展；validate_bundle 强制锚定声明。travel_planning/device_maintenance 迁移为「事实+声明物化视图」（Flight 等类型化行由事实谓词重建，materialized_from 回溯）。
- **三集合 campaign**：评测器去 conv-26 硬编码（conv-26 四口径、conv-47/49 原始 gold 两口径；判题实现与 11 文件锁零改动）；`ExperimentSpec` + `CampaignController`：预检门 → B0 门（全完+双故障零）→ Rn 无限迭代（`--stop` 叫停）→ 候选锁定（B0+全部采纳版）→ 统一验证 → 选版（原始严格>B0 且宽松≥、零故障、同分取早）→ 测试一次性揭盲（指纹相同单跑）；逐题台账 + 可选安全上限；验证/测试诊断封存前不进提案。
- **反例扩充**：事实级固定反例（否定/计划分别保存、重复按身份去重、增删事实图随之确定变化、改名/换日期身份跟随内容）接入每次装配后的 run_probes。
- 离线检查 98（根 tests）+ 11（travel）+ 10（冻结评测协议）= 119 项全绿。仓库外验收重跑于 `/private/tmp/oak-v04-portability/`：独立 venv 安装 `dist/oak_repro-0.4.0-py3-none-any.whl`（44 个包文件仅含 oak），仅拷贝第三任务声明/资产与示例，`python -I` 且清除 PYTHONPATH 后跑通 ExtractionAgent→MemoryResult→GraphAssembler→AnswerAgent 与 S/F/C/P（录制传输，不代表模型性能）。真实预检与 atomic_v1 实验记录待运行后补记于此。
