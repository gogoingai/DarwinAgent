# Oak 框架修复与 LoCoMo 三集合重跑

开始日期：2026-10-02。执行依据：`PORTABILITY-PLAN.md` 及用户追加要求。

## 本轮边界

- 内核分为 **S / F / C / P / H**。H 是 harness，指检索、工具执行、上下文组织、候选与输出核查等可版本化运行策略。
- 框架底线、模型传输、预算持久化和文件事务属于引擎，不因加入 H 就成为任意自动修改代码的入口。
- 用户明确禁止修改评测。本轮保留现有 judge、protocol、归因器、gold 修复表和数据内容；日期等评测依赖也冻结。共享拒答常量所在 `prompts/answer.py` 一并保持不变，新的生成策略置于领域 harness。
- 框架修复按契约、可靠性与已验证的移植能力验收；<3% 不作为框架修复验收条件。
- 后续迭代的收敛目标是冻结归因口径下 **评测外错题数 / 全部题目数 < 3%**。执行/评测未完成不能报达标；严格小于通过整数交叉乘法判断，避免四舍五入误报。
- 正文、observation、event_summary 的来源范围沿用当前系统，报告披露；没有增加外部答案来源。

## 已实施的第一批修复

- 实体、属性、主键、dtype、关系签名和 functional 冲突在通用建图入口校验；隔离模式明确记录污染候选。
- 节点 ID 改为保留结构和类型的序列化，避免字段分隔符造成错误合并；新图记录格式版本。
- 抽取端白名单由本轮 Schema 生成；图指纹包含完整语料和构建资产，生成续跑绑定图与 harness。
- event_summary 具有独立来源定位，终答仍标为摘要，不能因补齐定位就提升为正文证据。
- 内核登记增加 H、完整摘要及执行依赖；提供资产导出/装载和独立候选补丁，评测不是合法补丁目标。
- fast 未显式配置时继承主服务；角色路由可以通过配置注入。
- 显式命名空间预算覆盖其子调用，预留计数原子写入并支持重启恢复。
- 槽位提取器改为与图一致的上下文隔离；生成函数试跑超时可以结束工作进程。
- 形式推理未完成明确成为 UNVERIFIED，要求 HermiT 的调用不会将其当作通过。
- 统一构建与推理阶段入口已接入 LoCoMo；输出证据完整性与拒答协议检查在发布评测前执行。

追加修复：旅行领域计算迁入 `oak_domains`；领域角色不再登记在核心；两任务接入公共阶段编排。预算加跨客户端/进程文件锁并同时检查嵌套 scope。关系算子统一读取主键视图；形式映射修正 union domain 和实际 min/max 基数。候选补丁用临时目录验证后发布。

这些修复尚不表示整份可移植方案全部完成。完整自动学习控制器、领域模块独立执行、资产增删与自动采纳门控仍未完成，详见 `PORTABLE-USAGE.md`；本轮真实成绩按实际完成情况更新。
