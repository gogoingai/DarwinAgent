## 已授权目标与不可变约束

用户要求不断优化，仅使用 MiniMax，达到原生标准并完成全量测评。延续本地执行，不使用 Docker 或 Langfuse；保留所有历史证据和预算账本；旧 GLM 未知请求保持暂停。不得发布、推送、发版或向上游发送消息。

固定 LIFT `9d282e415c5e3b0f65b82c8758a013b269583d93`，EALE `419789ed1662e7b9ad16aa6620a4b31449612948`。全量为 14 场景、56 warmup、28 holdout，共 84 任务。模型和端点、私有运行时凭据、temperature=0、adaptive thinking、reasoning_effort=max、max_completion_tokens=16384 沿用当前 MiniMax 配置。模型请求上限继续为 null，沿用已有共享实际请求账本，不重置。

## 设计与判定

在现有 LIFT 接入上增加全量数据集、场景级控制器及本地能力。保留既有单场景类和 CLI 默认值，旧运行仍按旧身份恢复。每个场景独立训练、选版、工作区和轨迹；使用场景与题号组成任务标识，防止不同场景的 q1 覆盖。原始文件哈希固定，任务向 Agent 只暴露 query 和附件；隐藏内容与轨迹要求仅供评审。

新全量实验使用 LIFT CLI 的原生 30 轮交互上限，三组一致，达到 success=true 时提前结束。之前 3 轮实验属于独立历史协议，不与新成绩拼接。A 是原始 ReAct，B 是同一 ReAct 加 K0，C 加所选 K1。基础工具权限、模型和交互上限保持相同；组合函数展开调用独立计数。

每场景 q1/q2/q3 作为 warmup 轨迹及进化来源，q4 仅作候选验证，全部 4 个训练任务均实际执行。选版仍要求成功率、内容分不下降，持平再依次比较纠错、底层调用和 token；错误或不完整评审不能采纳。q5/q6 用于冻结版本的 A/B/C 比较，评审反馈不进入提案器。之前已看过的销售 q5/q6 明确标记为已观察测试，不能宣传为新独立泛化证据。

任务达标采用原生内容 success=true、score=1，同时单独报告原生轨迹评审得分；不得用禁用轨迹评审产生的固定 1 冒充测量。完整性与达标分开：全部任务必须有终态、失败不能丢弃；C 未达标任务仍保留为未达标，不因运行结束宣称目标完成。训练验证上的框架修复和 S/F/C/P 优化可以迭代；每次源代码或配置变化新冻结身份，A/B/C 重新执行。不能无限使用已观察 holdout 选版并声称独立确认。

## 实施任务与验收

1. 全量数据：新增独立 FullLiftDataset，哈希校验和路径边界沿用旧契约，明确 train/test 访问投影。验收 14×6 任务完整、复合标识不碰撞、隐藏规则不进入公开任务、单任务附件隔离、篡改/符号链接/遗漏拒绝，旧数据集测试通过。
2. 本地执行能力与协议：新增全量控制器，30 轮为显式身份字段，按场景训练验证并隔离测试；按公开训练任务需要补充搜索、网页读取和产物工具，网络故障留回执；不执行任意宿主机代码，不读私有配置。验收失败继续后续任务、已知回执不重放、未知写入暂停、旧默认兼容。
3. 原生轨迹评审：从真实按时间顺序的消息与工具回执构造原生输入，调用固定 MiniMax，纳入同一账本。离线验证输入语义、失败和重复恢复；不能虚构轨迹、模拟得分或截断后当完整轨迹。
4. 训练诊断及优化：真实运行全部训练题，分类框架/Agent/工具/评审问题；每项修复保存失败复现、原因、修改和复测。候选只从训练证据产生，验证摘要受控，S/F/C/P 优化空间保留。
5. 全量冻结测评：先离线验收，再固定源代码、工具、配置和 K1；执行 28×3 个 holdout 单元，内容与轨迹评审完整。一轮全量为首要覆盖目标，不把重复次数冒充独立任务数量。未达标保持目标未完成，诊断与独立结果分开。
6. 交付与回归：报告全部 84 原始任务的覆盖、所有 84 个 holdout A/B/C 单元、失败退化、时间/token/实际请求/展开工具及进化额外成本；中英文复现说明及贡献草稿；相关检查和必要框架/LoCoMo/TravelPlanner 回归。任何发布另行授权。

## 执行判断记录

- Ruling: 全量采用数据发布者的 14×6，而不是 README 示例中的任意 holdout 数量 — 数据说明和固定版本为权威 — 判断错误需重建任务清单及重跑缺失任务。
- Ruling: 新协议采用 CLI 原生 30 轮，保留旧 3 轮身份 — 每轮只反馈一个缺项，原诊断上限不能代替全量协议 — 调整错误需三组统一重跑，旧记录保留。
- Ruling: 首轮全量使用一次完整重复，先保证覆盖与真实达标 — 用户未要求统计重复数，三轮重复不能替代缺失场景 — 如需统计结论，追加同一冻结版本重复并单独报告。
- Ruling: 销售 holdout 已观察，明确列为已观察而不伪装独立 — 防止利用历史诊断扩大泛化结论 — 真正独立确认需要其他未参与调优任务或新数据。
- Ruling: 为新增轨迹评审角色保存可审计的兼容登记，沿用同一 MiniMax 共享计数与暂停入口 — 原始 transport 身份固定角色表，直接增加角色会拒绝恢复；另起共享目录可能绕过未知请求门禁 — 判断错误需修复登记并重新冻结实验，原始 policy、回执、计数不改写。
- Ruling: 联网能力通过真实检索结果验证，而非仅看 HTTP 200 — Bing RSS 探测出现无关结果，改用已验证的 DDG Lite；宿主 DNS fake-IP 使用固定公开 DoH 校验 — 外部提供方变化仍可能造成任务失败，必须记录，不应静默当空结果或成功。
