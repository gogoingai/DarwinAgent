# Oak 框架改造：实施与验收

本文件以 2026-10-03 确认方案为准，替换旧 H/domain/callback 方案。固定框架掌握执行；数据集实现输入适配和独立评测；只优化受能力约束的 S/F/C/P。目录、类图、能力边界见 [架构](ARCHITECTURE.md)，入口见 [使用说明](PORTABLE-USAGE.md)。

## 已实施

- 标准生成输入/来源/结果、独立评测接口、冻结 RunConfig。
- 正向 AST 解释器、只读数据算子、S/F/C/P 登记/版本/迁移/篡改检查。
- 固定 ExtractionAgent、AnswerAgent 和唯一 Pipeline；实际执行当前资产，含完整图拒答审查、候选审查和有界反馈。
- 固定图类型、来源、Schema/图实例公理与发布检查；C 只返回意见，不改写结果。
- 通用冷启动、结构化提案、独立候选、完整评分、冻结策略与原子发布控制器。
- LoCoMo/TravelPlanner 两个适配与评测实现，共同生成类；任务逻辑归入登记资产。
- 删除活动 H、`oak_domains`、数据集私有生成循环和发布后补项/替换；保留评测锁、历史记录和冻结代码。

## 离线验收

核心、接入及完整迭代控制器测试 77 项；冻结 LoCoMo 评测和迁移旅行资产测试 21 项。合计 98 项通过。覆盖越权调用、文件/网络/模型调用、输入修改、保留检查 ID、提示插槽、错误类型、伪造来源、工具未登记、资产篡改、故障伪装拒答/成功、审查失败发布、拒答反馈、恢复身份和并发来源隔离。还包括人数/费用/入住/日期/城市改名的资产行为反例、独立评测目录和故障记录。完整控制器用显式录制传输实际执行初始化、两轮提案、评分、严格增分采纳、同分拒绝、基准指纹拒绝和原子发布；不代表真实模型优化收益。

LoCoMo 生成输入 199 题，含三种已披露语料层，参考字段变更不会改变输入。TravelPlanner 45 条训练样本全部通过契约；一条真实适配输入用显式录制响应跑通共同 Pipeline 和原官方评测桥接，评测故障为 0，该检查不代表模型性能。11 个评测锁文件保持原 SHA256。仓库外安装 0.3.2 wheel 后，第三任务只带两个接入接口和任务资产，在隔离环境中跑通共同两个 Agent 与 Pipeline。

额外图级反例曾发现 cardinality min=1 没有阻止空关系图，因此在形成分数基线前中断 0.3.0 的启动记录，保留为失败，发布 0.3.1。随后 0.3.1 初始化调用的 completion 预算全部被思考消耗，没有返回资产正文；保留失败记录，在 0.3.2 中关闭初始化和提案角色的思考模式，重新冻结配置并启动冷启动基线。两次调整都发生在有效评分基线形成前，属于工程修复和运行配置修订，不能算资产迭代收益。

## 真实冷启动实验

实验目录 `datasets/locomo/runs/framework_v032_cold_20261003/`。仅使用 conv-26 训练语料和问题，现场生成 S/F/C/P，不使用历史种子、图、答案、提示或缓存。已获用户授权，固定路由为智谱 glm-5.3 和 CommandCode deepseek/deepseek-v4-flash-fast；原始/修订 gold 只供独立冻结评测，不进入生成。

计划要求 B0/R1/R2 各完整运行 199 题，独立建图、答案和评测缓存。每轮一个候选包；修订 gold 精准通过题数严格增加，其他三个口径不下降，生成故障不增加，且完整评测无评测故障，才能采纳。同分拒绝，两轮后停止。验证集与测试集按完整会话划分（conv-47/conv-49），只在候选锁定后运行：统一验证选版、测试一次性揭盲，逐题诊断封存前不进提案，不据此声称泛化或收敛。

实验状态以运行目录中的 `stage.json/evaluation.json/decision.json/summary.json/failure.json` 为准。未完成阶段明确失败，不能用录制响应或冒烟分数替代真实 199 题结果。

实际结果：B0、R1 都在抽图阶段失败，各保存 199 条执行错误，有效评测题数为 0。R2 的提案基准指纹有一字符错误，准入拒绝，未进行建图、199 题作答或评测。两轮停止、采纳 0 个修订，`summary.json` 明确为 `failed`。四种指标中的 0 是故障占位，不能报告为有效基线成绩或资产改善。详细原因、调用量和验收范围见 [修复与实验记录](FRAMEWORK-REPAIR-LOG.md)。
